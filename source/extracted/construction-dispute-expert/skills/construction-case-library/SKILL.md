# 工程管理实战案例库（185 篇）

## 这是什么

本机收录的 185 篇工程管理实战案例（口播/短视频文字稿，作者视角为施工单位与分包实践），已全部转成可检索文本并蒸馏成 13 份主题判据笔记。

**用途**：给「工程纠纷处理专家」的分析**补事实、补行情、补同类先例**——让结论不是凭常识推的，而是有案可查。

**性质提醒（必须守住）**：这是**行业实践素材**，不是法律依据，不是裁判文书，不是官方口径。作者表达的是个人经验与地区行情。

## 检索流程（四步，不要跳）

1. **定位主题** —— 读 `references/00-总索引.md` 第一章「主题导航」，确定命中 1–3 个主题笔记。
2. **拿判据与案例** —— Read 对应 `references/<编号>-<主题名>.md`。每份含五节：核心判据表 / 典型争议与处置路径 / 必备证据与手续清单 / 高频踩坑与风险三档 / 本主题素材清单。
3. **找同类先例** —— 需要更多同题材案例时，用脚本按关键词全库检索：

   ```bash
   "C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe" \
     "<本技能目录>/scripts/search_cases.py" "审计 核减 签证" --limit 12
   ```
   **检索技巧**（实测）：默认是 AND（同篇须全部命中）。关键词可以写成独立参数，也可以整体加引号——**脚本会自动按空白拆分，两种写法等价**。AND 命中不足时加 `--or` 改并集。加 `--notes` 则改在 13 份主题判据笔记里搜（找"规则"用 `--notes`，找"案例"用原文库）。命中 0 时先减到 1–2 个词再试，并换同义词（审减→核减→扣减；计量→方量→确认单；签字→签认→签名→授权），不要一次就下"库里没有"的结论。
   也可直接用 Grep 在 `references/原文库/` 里搜关键词，或搜 `references/00-总索引.md` 的「关键词速查」表。
4. **调原文原话** —— 需要作者原话、具体金额与流程时，Read `references/原文库/<三位编号>-<标题>.txt`（编号即总索引里的案例编号）。

## 引用纪律（重要）

1. **必须标编号**。引用任何判据或案例时写清「案例 ×× 号」，便于回溯原文。例如：〔案例 116〕〔案例 175〕。
2. **不得把素材当法条**。稿中出现的法条条号（如《招标投标法》第五十三条）**可能过期或有口误**，只能作为"线索"，正式援引前必须以现行有效版本核对。引用格式：`【素材提及】`+ 现行条文另核。
3. **金额与比例必须带口径**。稿中数字（40 元/立方、下浮 10 个点、15% 调价线）属于作者当时当地的行情，跨地区跨年份使用要写明"素材口径为 ×× 地区 ×× 年"。
4. **区分「作者主张」与「通用规则」**。作者给的处置建议是个案经验，用 `【素材经验】` 标注，不要写成"应当""必须"。
5. **不覆盖专家纪律**。本库只是事实与先例来源；专家的边界不变——不出正式法律意见书、不承诺结果、缺资料列缺口清单、涉刑线索单独提示。
6. **第 14 篇原文为空**，全库实际可读 184 篇。

## 与其他技能的配合

本专家包的技能回答不同层面的问题，**顺序不能倒**：

| 顺序 | 依据 | 取什么 |
|---|---|---|
| 0 | 项目自身的**合同专用条款与补充协议** | 效力最高的一层，任何纠纷先看这一项 |
| 1 | 现行建设工程**法律法规与司法解释** | 到了裁判机构面前主张能不能站住 |
| 2 | `tianxing-institution-library`（公司制度库） | 公司内部流程口径（**先过「效力状态总表」**） |
| 3 | **本库**（案例库 185 篇） | 行业先例与判据 |
| 4 | `construction-dispute-toolkit` | 七段式加一附骨架，落成可贴进汇报的成文 |

- 反之亦可：工具包搭好框架后，用本库给每一栏填具体判据与同类案例。
- **本库与公司制度库结论不一致时**，明确写出不一致在哪，再给取舍建议，不强行调和。
- 本库讲"行业上怎么做"，制度库讲"本公司怎么规定"——**不要把两者混作一谈**。
